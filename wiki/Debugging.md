# Debugging

## Breakpoints

### Address breakpoints (F9 / direct)

Press **F9** in any editor, or use the command **CPC: Add breakpoint at address/label**. Enter a hex address (`0x4000`, `4000`) or a label name. The breakpoint appears in the VS Code **Breakpoints** panel as a function breakpoint.

Breakpoints are persisted across sessions in workspace state and re-applied automatically at the start of each debug session.

### Source breakpoints (.asm files)

Click in the gutter of a `.asm` source file to set a breakpoint on a source line. The extension resolves the address from the RASM symbol map (`.rasm` super snapshot) and sends it to the emulator. Source breakpoints and address breakpoints are fully synchronized.

### Label breakpoints

In the **Add breakpoint** dialog, type a label name as defined in your RASM source (`MAIN`, `LOOP`, `DRAW_SPRITE`…). The extension resolves the address from the symbol table at session start.

## Breaking from assembler code — `ED FF`

Insert the two-byte sequence `ED FF` anywhere in your Z80 code to trigger a software breakpoint:

```asm
    ; ... some code ...
    DB $ED, $FF      ; software breakpoint — pauses in VS Code
    ; ... continues here after F5 ...
```

When the CPC CPU executes `ED FF`, SugarboxV2 sends a `break_` event and VS Code pauses at that address.

## Stepping

| Action | Key | Z80 behaviour |
|--------|-----|---------------|
| Step Over | F10 | Executes one logical step; `CALL` instructions execute to completion |
| Step Into | F11 | Executes one instruction; enters `CALL` targets |
| Step Out | Shift+F11 | Runs until the current `CALL` frame returns (next `RET`) |
| Continue | F5 | Resumes execution until the next breakpoint or `ED FF` |
| Pause | F6 | Pauses a running emulator |

**Note on Step Over and `DJNZ` / `LDIR`:** Step Over completes the loop in a single step, which may take many CPC cycles but returns immediately in VS Code.

## Registers and Variables panel

While paused, the VS Code **Variables** panel shows all Z80 registers:

- Main registers: `AF`, `BC`, `DE`, `HL`, `IX`, `IY`, `SP`, `PC`
- Alternate registers: `AF'`, `BC'`, `DE'`, `HL'`
- Special: `I`, `R`, interrupt flags

Values are displayed in hexadecimal. You can edit a register value directly in the panel.

## Watch expressions

In the **Watch** panel, add expressions:

| Expression | Result |
|------------|--------|
| `AF` | Value of the AF register pair |
| `PC` | Current program counter |
| `(0x4000)` | Byte at memory address 0x4000 |
| `MAIN` | Address of label `MAIN` (from symbol table) |

Unknown expressions return `?`.

## RASM super snapshot

If your project uses [RASM](https://rasm.me/), pass the `.rasm` super snapshot as `program` in `launch.json`. The extension loads:

- **Symbol table** — all labels become usable as watch expressions and breakpoint targets
- **Source map** — each address maps to a `.asm` file and line number, enabling gutter breakpoints and PC highlighting in the source editor

The `.rasm` file is generated by RASM with the `-sp` flag:

```bash
rasm main.asm -o main.sna -sp main.rasm
```
